GAM으로 일괄 적용

GAM 안내서

Google Workspace 최고관리자 계정이 필요합니다. 처음에 GAM 설치와 권한 연결을 한 번 해 두면, 그 뒤로는 3~5단계만 반복합니다.

  1. GAM 설치맥·리눅스 터미널에서 bash <(curl -s -S -L https://git.io/gam-install)를 실행합니다. 윈도우는 GAM 안내서의 설치 파일을 씁니다.
  2. 권한 연결gam create project → gam oauth create(기본 선택 그대로 c) → gam user 관리자@igt.or.kr check serviceaccount 순서로 실행합니다. 마지막에 나오는 링크로 관리 콘솔의 ‘도메인 전체 위임’을 승인하는데, 범위 칸에는 https://www.googleapis.com/auth/gmail.settings.basic 하나만 남기는 것을 권합니다. 서명에는 이 권한만 필요하고, 나머지 범위는 FAIL로 남아도 됩니다.
  3. 배포 파일 받기서명 만들기 ①의 ‘관리자: 전체 구성원 불러오기’로 DB를 불러오고, 전체 선택 → ④의 ‘관리자: 배포 파일’ › 배포 파일 ZIP을 받아 압축을 풉니다.
  4. 이미지 올리기ZIP 안 저장소에_올릴_파일/assets 폴더를 저장소(minskapo/igt-namecard) 맨 위에 덮어쓰고 커밋·push 합니다. 1~2분 뒤 이미지_주소_확인.txt의 주소가 열리면 준비된 것입니다.
  5. 일괄 적용압축을 푼 폴더에서 gam csv gam/signatures.csv gam user '~email' signature file '~file' html을 실행합니다. 맥(zsh)에서는 작은따옴표를 꼭 붙여야 합니다. 한 사람만 바꿀 때는 gam user minski@igt.or.kr signature file gam/html/minski.html html처럼 씁니다.
  6. 확인·공지gam user minski@igt.or.kr show signature로 확인합니다. 일괄 적용하면 각자 넣어 둔 기본 서명이 바뀌므로, 적용 전후에 구성원에게 알리고 Gmail 서명 정리 안내를 함께 보냅니다.

일괄 적용은 사람마다 서명 하나(DB의 ‘서명 언어’)만 넣습니다. ‘--’ 줄과 여러 서명 관리는 Gmail API로 바꿀 수 없어 구성원이 각자 설정합니다.

신규 구성원·정보 변경

  1. DB에 적기DB 시트 ‘구성원’ 탭에 한 줄을 넣습니다. 이메일 아이디·이름·부서·직급·핸드폰·이메일만 채우면 영문 이름과 직함은 자동으로 채워집니다. 영문 이름은 본인 표기를 확인합니다. 퇴사자는 ‘상태’를 퇴사로 바꿉니다.
  2. 배포 파일 받기DB를 다시 불러와 그 사람만 골라 배포 파일 ZIP을 받습니다. 서명 코드가 없던 사람은 새 코드가 서명코드_DB기록.csv에 적혀 나오니, DB ‘서명 코드’ 칸에 꼭 옮겨 적습니다.
  3. 추적링크 기록추적링크 시트 행 복사를 누르고 추적링크 시트 ‘UTM코드 생성기’ 탭 맨 아래 빈 행의 A열에 붙여 넣습니다. 사람마다 5줄입니다.
  4. 올리고 적용위 4~5단계처럼 이미지를 올리고 그 사람만 gam user …로 적용합니다.
  5. 정보가 바뀌면서명 코드는 그대로 두고 DB를 고친 뒤 같은 과정을 반복합니다. 직함만 바꾸는 경우는 구성원이 직함 바꾸기로 직접 할 수 있습니다.

추적 링크 규칙: 버튼 링크에는 utm_source=signature · utm_medium=email · utm_campaign=email_signature · utm_content=이메일 아이디 · utm_term=누른 곳(donate·newsletter·homepage·website·card)이 붙습니다. GA4에서는 세션 소스/매체 signature / email로 봅니다. LinkedIn 버튼에는 붙이지 않습니다.

처음 한 번 설정

Google 로그인 연결 (완료됨)

Google Cloud에서 Sheets API를 켜고, OAuth 동의 화면을 내부로 만든 뒤, 웹 애플리케이션 클라이언트 ID(승인된 JavaScript 원본 https://minskapo.github.io)를 만들어 js/db-load.js의 clientId에 넣었습니다. 로그인할 때 ‘관리자가 차단한 앱’이 뜨면 관리 콘솔 › 보안 › API 제어에서 ‘도메인 소유의 내부 앱 신뢰’를 켭니다.

구성원 셀프 반영 웹앱 (내 정보 불러오기·직함 바꾸기)
  1. GitHub 토큰GitHub 토큰 만들기에서 Repository access를 Only select repositories › minskapo/igt-namecard로, Permissions › Contents를 Read and write로 정하고 만료를 1년으로 둡니다.
  2. 스크립트 만들기DB 시트 소유자 계정으로 script.new를 열고 저장소의 tools/sig-self.gs 내용을 붙여 넣습니다. 프로젝트 설정 › 스크립트 속성에 GITHUB_TOKEN을 추가합니다.
  3. 웹앱 배포배포 › 새 배포 › 유형 웹 앱, 실행 계정 나, 액세스 권한 모든 사용자로 배포하고 권한을 승인합니다. 연구소 계정 확인은 스크립트가 직접 하므로 ‘모든 사용자’로 둬야 페이지에서 호출할 수 있습니다.
  4. 연결웹앱 URL(https://script.google.com/macros/s/…/exec)을 js/db-load.js의 selfUrl에 넣고 push 합니다.

웹앱은 로그인한 사람의 DB 한 줄만 돌려주고, 이미지는 그 사람의 서명 코드 폴더에만 올립니다. DB에는 국문·영문 직함만 적습니다. 토큰이 만료되면 1단계부터 다시 하고 스크립트 속성만 바꿉니다.

관리자 문제 해결

GAM에서 권한 오류가 나요

gam user 관리자@igt.or.kr check serviceaccount를 다시 실행해 gmail.settings.basic이 PASS인지 확인합니다. 승인 직후에는 몇 분 걸릴 수 있습니다.

zsh: no such user or named directory: email

맥 터미널이 ~email을 홈 폴더로 읽은 것입니다. '~email', '~file'처럼 작은따옴표로 감싸 주세요.

이미지를 올렸는데 서명에 반영되지 않아요

이미지만 올리고 서명을 다시 적용하지 않으면 예전 주소(?v= 값)가 남습니다. 배포 파일을 새로 받아 다시 적용합니다. Gmail은 이미지를 한동안 저장해 두므로 바로 바뀌지 않을 수 있습니다.

셀프 반영이 실패해요

웹앱 URL, GITHUB_TOKEN 만료, DB에 그 사람의 서명 코드가 있는지를 차례로 확인합니다. 스크립트 편집기의 ‘실행’ 기록에서 오류 내용을 볼 수 있습니다.
